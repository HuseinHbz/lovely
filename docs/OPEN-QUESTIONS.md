## ۳. کمبودهای اسکیما

اسکیمای فعلی (`بخش ۵` سند فازبندی) این موارد را پوشش نمی‌دهد:

1. **`act: 1 | 2 | 3 | 4 | 5`** — داستان جدید ۹ فصل دارد. باید به `1..9` تغییر کند.
2. **مرحله ۱۳ (دکمه‌ی «نمی‌دونم»)** — هیچ `kind` موجودی این را پوشش نمی‌دهد. پیشنهاد:
   ```ts
   | { kind: 'repeat'; label: string; phrases: string[]; threshold: number; message: string }
   ```
3. **مرحله ۱۹ (کشوها)** — `split` جای واکنش «رد شدن» برای جای اشتباه ندارد، ولی داستان سه واکنش مشخص دارد. پیشنهاد:
   ```ts
   rejections?: { cardId: string; bucketId: string; reaction: string }[]
   ```
4. **مرحله ۲۰** — دو تعامل پشت سر هم (سفارش + پاسخ نهایی) و بعد سه دکمه‌ی پایانی. اسکیما فقط یک `interaction` per stage دارد. پیشنهاد: `interactions: Interaction[]` به‌جای `interaction`، به‌علاوه‌ی بلوک `endings`.
5. **صفحه‌ی ورود و صحنه‌ی مخفی** — هیچ‌کدام Stage نیستند. پیشنهاد: `content/cover.ts` و `content/easter-eggs.ts` جدا.
6. **`Speaker`** — `'squirrel'` در داستان جدید اصلاً استفاده نمی‌شود؛ `'nazoo'` همان پاندای بازپرس است (در پایان سوم «نازو» صدا زده می‌شود). تأیید می‌کنی که نازو = پاندا و سنجاب حذف شود؟

## ۵. موارد کوچک‌تر

- **نام برندها.** «ایرانسل» (مرحله ۳ و ۱۴) و «سشوار انزو» (مرحله ۷) در متن هستند. قاعده ۴ درباره‌ی نام و عکس *اشخاص* واقعی است، نه برند، پس فعلاً می‌مانند — ولی برای فهرست کلمات ممنوعه‌ی فاز ۷ باید تکلیفشان روشن باشد.
- **«پاسخ درست»** در مراحل ۳، ۶ و ۸ با قاعده‌ی «هیچ گزینه‌ای کاربر را غلط اعلام نمی‌کند» تنش دارد. پیشنهاد: پاسخ داستانی مُهر «ثبت شد» بگیرد، بقیه مُهر «مشکوک» + یک جمله‌ی خنده‌دار، و همه به مرحله‌ی بعد بروند. این جمله‌های خنده‌دار جزو همان ۳۳ مورد بند ۲ هستند.
- **تناقض داخلی سند فازبندی.** قاعده ۱ هنوز مرحله ۳ را نمونه‌ی `pending-content` معرفی می‌کند، در حالی که فاز ۰ می‌گوید محتوا تحویل شده. یک جمله اصلاح لازم دارد.
- **نام پوشه.** سند `wolf-and-hedgehog/` را ریشه فرض می‌کند؛ مخزن واقعی `lovely` است. پیش‌فرض من: همان ساختار در ریشه‌ی `lovely` پیاده شود.
