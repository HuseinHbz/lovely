# مهاجرت به نسخه ۲ — ۲۸ برگه در ۶ دفتر

**تاریخ:** ۱۵ مرداد (۲۰۲۶-۰۸-۰۵)
**منبع حقیقت جدید:** `docs/MERGED-SPEC.md` (نسخه ۲٫۰) + `docs/STORY-28.md`
**منسوخ‌شده:** `docs/STORY-v1-superseded.md` (ساختار ۲۰ مرحله‌ای)

این فایل صادقانه می‌گوید از کدی که تا الان ساخته شده چه چیزی زنده می‌ماند، چه چیزی باید عوض شود و چه چیزی مرد. بدون این حساب، وقت روی چیزی خرج می‌شود که دیگر وجود ندارد.

## ۳. چه چیزی باید عوض شود

### ۳٫۱ اسکیما — `content/schema.ts`

| فیلد      | حالا                                           | باید بشود                                                            |
| --------- | ---------------------------------------------- | -------------------------------------------------------------------- |
| `id`      | `/^s\d{2}$/` → `s01`…`s20`                     | `/^p\d{2}$/` → `p00`…`p27`                                           |
| `act`     | `1..9` (فصل)                                   | `1..6` (دفتر)                                                        |
| `Speaker` | `nazoo, wolf, hedgehog, owl, squirrel, system` | `nazoo, wolf, hedgehog, owl, abi, system` — سنجاب حذف، **ابی اضافه** |
| —         | —                                              | `panda:` لایه‌ی پاندا برای هر برگه (متن ثبت مدرک)                    |
| —         | —                                              | `achievement?:` نشانی که این برگه باز می‌کند                         |
| —         | —                                              | `meters?:` دلتای شش شاخص طنز                                         |

راوی جداگانه لازم نیست: `MERGED-SPEC` می‌گوید راوی **همان پاندا** است، پس `nazoo` هر دو نقش را دارد.

### ۳٫۲ تعامل‌های تازه

آنچه داریم: `choice`, `pick`, `sort`, `find`, `split`, `repeat`.
آنچه سند جدید می‌خواهد و نداریم:

| برگه | تعامل                 | چه چیزی لازم است                    |
| ---- | --------------------- | ----------------------------------- |
| ۰۲   | چت                    | UI حباب پیام مثل مسنجر              |
| ۰۳   | جنگ لقب               | `NICKNAME UNLOCKED` با انیمیشن ورود |
| ۱۲   | کی زودتر می‌خوابد     | مینی‌بازی                           |
| ۱۳   | قرارداد بغل           | امضا / اصلاح بند                    |
| ۱۵   | نجات کفش از گل        | مینی‌بازی                           |
| ۱۶   | پک کردن کلاه‌ها       | کشیدن و رها کردن                    |
| ۱۷   | حدس غذا               | حدس بدون جریمه                      |
| ۱۸   | جور کردن قرار با شیفت | تقویم                               |

`repeat` که برای دکمه‌ی «نمی‌دونم» ساخته بودم **دیگر مصرفی ندارد** — آن صحنه در ۲۸ برگه نیست. یا حذف می‌شود یا برای مینی‌بازی جدیدی بازاستفاده.

### ۳٫۳ اسکین‌های تازه

| اسکین         | برای                                                |
| ------------- | --------------------------------------------------- |
| `ChatSkin`    | برگه‌های ۰۲، ۰۴، ۰۹، ۱۲ — UI مسنجر                  |
| `CourtSkin`   | برگه‌های ۰۵ و ۲۲ — دادگاه کارتونی، چکش، جایگاه متهم |
| `SummarySkin` | برگه ۲۶ — برگه‌ی خلاصه‌ی پرونده با شش شاخص          |

`MapSkin` می‌ماند ولی محتوایش عوض می‌شود (پایین).

### ۳٫۴ استور — `lib/store.ts`

شش شاخص طنز اضافه می‌شوند. قاعده‌ی سفت از `MERGED-SPEC` بخش ۴: **هیچ شاخصی هیچ صحنه، پایان یا محتوایی را قفل نمی‌کند** و هیچ عددی نمی‌گوید «رد شدی». فقط برای طنز و برگه‌ی خلاصه‌ی پایانی‌اند.

به‌علاوه: دستاوردهای باز‌شده. همه در همان `localStorage` — قاعده ۲ دست‌نخورده.

### ۳٫۵ نقشه — `content/map.ts`

نُه نقطه‌ی فعلی (بیمارستان، تراول‌ماگ، بلوار دوردور، …) از داستان نسخه ۱ می‌آمدند. سند جدید یک **نقشه‌ی داستان** با پانزده گره دارد (`STORY-28.md` بخش ۱۹): آشنایی → چت → لقب‌ها → دادگاه → پاندا → هدیه → شب → اژدها → غذا → بیرون → سوءتفاهم → قهر → ترمیم → اعتماد → فصل بعد.

از نُه نقطه‌ی قدیمی فقط «بیمارستان جغدها» بازمی‌گردد. بقیه باید جایشان را به گره‌های داستانی بدهند. کامپوننت `ForestMap` می‌ماند؛ داده‌اش عوض می‌شود.

## ۴. چه چیزی مرد

### ۴٫۱ سه فایل مرحله

`content/stages/s01.ts`, `s02.ts`, `s03.ts`:

- **s01 (احراز هویت)** → متن جدیدش در `MERGED-SPEC` بخش ۳ آمده و کاملاً بازنویسی شده. سؤال عوض شده: «آیا شما همان گرگی هستید که پرونده‌اش به قطر رمان شوهر آهو خانم است؟» با سه گزینه‌ی تازه.
- **s02 (معرفی گرگ)** → به‌عنوان مرحله‌ی مستقل حذف می‌شود.
- **s03 (اولین برخورد در بیمارستان)** → می‌شود **برگه ۰۱**، محتوایش تا حد زیادی زنده می‌ماند.

### ۴٫۲ بیشتر ۳۳ واکنش پیش‌نویس — این مهم است

`docs/03-stages-draft.md` را برای داستان نسخه ۱ نوشتم. با ساختار جدید:

| صحنه‌ی نسخه ۱                 | سرنوشت                                                        |
| ----------------------------- | ------------------------------------------------------------- |
| مرحله ۳ — اولین برخورد        | ✅ زنده، می‌شود برگه ۰۱ (۳ واکنش)                             |
| مرحله ۷ — زبان هدیه           | ✅ زنده، می‌شود برگه ۱۰ (۳ واکنش)                             |
| مرحله ۱۵ — استوری پاندا       | ✅ زنده، می‌شود برگه ۰۷ (۳ واکنش)                             |
| مرحله ۱۸ — اعتراف‌ها          | ⚠️ نیمه‌زنده، به برگه ۲۵ (ترمیم) نزدیک است ولی متن عوض می‌شود |
| مرحله ۲۰ — سفارش و پاسخ نهایی | ⚠️ نیمه‌زنده، برگه ۲۴ و ۲۷ ولی چهار پایان به‌جای سه           |

| مرحله ۱۶ — گل‌سر صورتی        | ❌ **وجود ندارد**                                             |

یعنی از ۳۳ پیش‌نویس، **۹ تا برای صحنه‌هایی است که دیگر وجود ندارند** و ۱۱ تا باید بازنویسی شوند. فقط ۹ تا مستقیم قابل انتقال‌اند.

**تا وقتی ساختار قطعی نشده، تأییدشان بی‌فایده است.** فایل پیش‌نویس دست‌نخورده می‌ماند تا متن‌های قابل نجاتش برداشته شود.

### ۴٫۳ چیزهایی که سند جدید صریحاً حذف کرده

از `MERGED-SPEC` بخش ۷ — این‌ها **پیاده نمی‌شوند**، حتی اگر در `STORY-28.md` آمده باشند:

- `PMS MODE` و آیکون‌هایش. سند خودش می‌گوید با قانون ۷ («جوجه‌تیغی نباید همیشه عصبانی نمایش داده شود») در تضاد است.
  → **اثر روی کد:** حالت `storm` جوجه‌تیغی که در آرت‌ورک ساختم باید یا حذف شود یا به یک حالت خنثی‌تر تغییر نام بدهد. منتظر تصمیم توام.
- شرط `Trust >= 80` و قفل `MARRIAGE PATH`.
- جمله‌ی «مسیر اصلی: TRUST → UNDERSTANDING → CHOICE → LOVE».
- جریمه‌ی `Wrong Guess -5`.
- **تمام نام‌های واقعی، در محتوا و در UI.** این همان چیزی است که از اول رعایت کرده‌ام؛ حالا در سند جدید هم قفل شده.

### ۴٫۴ مدل دیتابیس سند ۲۸ فازی

`STORY-28.md` بخش ۲۳ یک مدل دیتابیس دارد. **پیاده نمی‌شود.** `MERGED-SPEC` بخش ۹ قاعده‌ی «هیچ پاسخی ثبت یا ارسال نمی‌شود» را نگه داشته و `PHASE-PLAN` دیتابیس را از MVP حذف کرده. آن بخش صرفاً شکل داده را توصیف می‌کند و همان شکل در `localStorage` پیاده می‌شود.

## ۶. آنچه هنوز نوشته نشده — بدون این‌ها فاز ۴ شروع نمی‌شود

`MERGED-SPEC` بخش ۱۰ خودش سه مورد را باز گذاشته:

1. **دیالوگ برگه‌های ۲۶ و ۲۷** نوشته نشده.
2. **لایه‌ی پاندا برای هر ۲۸ برگه.** ستون آخر جدول‌های بخش ۶ فقط جهت‌گیری است، نه متن نهایی. یعنی ۲۸ متن کوتاه لازم است.
3. **تصمیم آرت‌ورک** — پایین.

به‌علاوه‌ی چیزی که خودم اضافه می‌کنم:

4. **گزینه‌های بازیکن برای هر برگه.** جدول‌های بخش ۶ می‌گویند «انتخاب واکنش گرگ» ولی خود گزینه‌ها و واکنش‌هایشان نوشته نشده‌اند. `STORY-28.md` برای بعضی برگه‌ها دیالوگ دارد ولی گزینه‌بندی ندارد. این بزرگ‌ترین حجم کار نوشتاری باقی‌مانده است.
