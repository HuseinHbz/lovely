# فاز ۸ — مرجع اسکریپت‌ها

پارامترها، کدهای خروج و نمونه‌ی خروجی هر اسکریپت. برای راهنمای استقرار `docs/08-deploy.md` را ببین.

همه با `set -euo pipefail` نوشته شده‌اند و همه `shellcheck -S warning` را تمیز رد می‌کنند.

---

## `install.sh`

```
sudo ./install.sh --domain <domain> --email <email> [options]
```

| پارامتر               | پیش‌فرض                  | توضیح                                   |
| --------------------- | ------------------------ | --------------------------------------- |
| `--domain <domain>`   | —                        | **لازم.** دامنه‌ی سایت                  |
| `--email <email>`     | —                        | لازم مگر `--no-ssl`؛ برای Let's Encrypt |
| `--dir <path>`        | `/var/www/wolf-hedgehog` | محل نصب                                 |
| `--port <port>`       | `3000`                   | پورت داخلی Next                         |
| `--expires <iso8601>` | یک سال بعد               | تاریخ انقضای لینک                       |
| `--no-ssl`            | خاموش                    | بدون certbot — فقط برای تست             |
| `-h, --help`          | —                        | راهنما                                  |

### کدهای خروج

| کد  | معنی                                                    |
| --- | ------------------------------------------------------- |
| ۰   | نصب موفق و سایت جواب داد                                |
| ۲   | آرگومان نادرست یا ناقص                                  |
| ۳   | بدون دسترسی root                                        |
| ۴   | `pnpm build` شکست خورد (ریلیز ناقص خودکار پاک شد)       |
| ۵   | پیکربندی Nginx نامعتبر است                              |
| ۶   | بررسی سلامت شکست خورد — سرویس بالا می‌ماند تا بررسی کنی |

### رفتار idempotent

اجرای دوباره چیزی را خراب نمی‌کند. مهم‌ترین بخشش: **اگر `.env` باشد دست نمی‌خورد.** بازتولید توکن یعنی باطل شدن لینکی که قبلاً فرستاده شده — پس اسکریپت ترجیح می‌دهد کاری نکند.

هر مرحله rollback خودش را دارد: اگر build شکست بخورد، ریلیز نیمه‌کاره پاک می‌شود و `current` دست نمی‌خورد.

## `update.sh`

```
sudo ./update.sh [--ref main] [--dir <path>] [--rollback]
```

| پارامتر        | پیش‌فرض                  | توضیح                                                |
| -------------- | ------------------------ | ---------------------------------------------------- |
| `--ref <ref>`  | `main`                   | شاخه یا تگ                                           |
| `--dir <path>` | `/var/www/wolf-hedgehog` | محل نصب                                              |
| `--keep <n>`   | `5`                      | چند ریلیز نگه داشته شود؛ روی دیسک تنگ `2`            |
| `--rollback`   | —                        | بازگشت به ریلیز قبلی؛ با آرگومان دیگری ترکیب نمی‌شود |

> هر ریلیز حدود **۱۸۰MB** به دیسک اضافه می‌کند، نه ۶۳۸MB: `node_modules` بین ریلیزها از انبار pnpm هاردلینک می‌شود و فقط `.next` یکتاست. جزئیات و اعداد اندازه‌گیری‌شده در `docs/08-deploy.md` بخش ۱٫۱.

### کدهای خروج

| کد  | معنی                                                               |
| --- | ------------------------------------------------------------------ |
| ۰   | به‌روزرسانی موفق و سالم                                            |
| ۲   | آرگومان ناشناخته                                                   |
| ۳   | بدون root، یا محل نصب وجود ندارد                                   |
| ۴   | ریلیز قبلی نیست (`--rollback`)، یا مخزن مبدأ پیدا نشد              |
| ۵   | بررسی سلامت شکست خورد و **بازگشت خودکار انجام شد** — سایت سالم است |
| ۶   | سایت پایین است و بازگشت هم جواب نداد                               |

> کد ۵ یعنی «به‌روزرسانی نشد ولی سایت سالم است». این حالت شکست نیست، محافظت است.

[5] بررسی سلامت
     ✓ سایت سالم است

     ✓ 1 ریلیز قدیمی پاک شد

 به‌روزرسانی تمام شد — بدون قطعی.

## `uninstall.sh`

```
sudo ./uninstall.sh [--dir <path>] [--purge] [--keep-cert] [--yes]
```

| پارامتر        | توضیح                                                 |
| -------------- | ----------------------------------------------------- |
| `--dir <path>` | محل نصب                                               |
| `--purge`      | کاربر سیستمی، پشتیبان‌ها، تایمر و قواعد ufw را هم ببر |
| `--keep-cert`  | گواهی Let's Encrypt را نگه دار                        |
| `--yes`        | بدون تأیید تعاملی                                     |

### کدهای خروج

| کد  | معنی                                     |
| --- | ---------------------------------------- |
| ۰   | حذف انجام شد                             |
| ۲   | آرگومان ناشناخته                         |
| ۳   | بدون دسترسی root                         |
| ۴   | تأیید مطابقت نداشت — **هیچ‌چیز حذف نشد** |

### تأیید

باید نام دامنه را تایپ کنی. اگر دامنه از Nginx خوانده نشود، واژه‌ی «حذف» خواسته می‌شود.

### نمونه

```
 حذف شد:
  − پروسه‌ی pm2 «wolf-hedgehog»
  − پیکربندی Nginx
  − گواهی Let's Encrypt
  − /var/www/wolf-hedgehog — کد، build و .env

 دست‌نخورده ماند:
  · /var/backups/wolf-hedgehog — پشتیبان‌ها
  · کاربر سیستمی wolfapp
  · قواعد ufw
  · Node.js، pnpm، pm2 و Nginx — بسته‌های سیستمی دست نخوردند

درباره‌ی داده‌ی کاربر: پیشرفت و انتخاب‌ها هیچ‌وقت روی این سرور نبودند —
فقط در localStorage مرورگر خودِ کاربر.
```

گزارش عمداً هر دو ستون را دارد. برای این پروژه «فکر کردم پاک شده» بدترین حالت ممکن است.

## `backup.sh`

```
./backup.sh [--dir <path>] [--out <path>] [--keep 14]
```

| پارامتر        | پیش‌فرض                      |
| -------------- | ---------------------------- |
| `--dir <path>` | `/var/www/wolf-hedgehog`     |
| `--out <path>` | `/var/backups/wolf-hedgehog` |
| `--keep <n>`   | `14`                         |

### کدهای خروج

| کد  | معنی                 |
| --- | -------------------- |
| ۰   | پشتیبان ساخته شد     |
| ۲   | آرگومان ناشناخته     |
| ۳   | `current` وجود ندارد |

### چه چیزی داخل آرشیو است

```
./.env        ← توکن و سکرت
./content/    ← متن پرونده
./MANIFEST    ← تاریخ، نام ریلیز، کامیت
```

آرشیو با مجوز ۶۰۰ ساخته می‌شود چون `.env` داخلش است.

**پیشرفت کاربر پشتیبان نمی‌شود و نباید بشود.** فقط در `localStorage` مرورگر خودش است و هیچ نسخه‌ای روی سرور وجود ندارد — همین قاعده ۲ است. اگر روزی این اسکریپت چیزی از انتخاب‌های کاربر را آرشیو کرد، یعنی جای دیگری از پروژه شکسته است.

### نمونه

```
پشتیبان: /var/backups/wolf-hedgehog/20260805-123910.tar.gz (24K) · 0 فایل قدیمی حذف شد
```

اجرای روزانه با تایمر systemd که `install.sh` نصب می‌کند:

```bash
systemctl status wolf-hedgehog-backup.timer
systemctl list-timers wolf-hedgehog-backup.timer
```

## `deploy/ecosystem.config.cjs`

پیکربندی PM2. مقادیر را از محیط می‌خواند (`WH_DIR`, `WH_PORT`, `WH_USER`) تا هم مستقیم قابل استفاده باشد و هم `install.sh` بتواند نسخه‌ی نهایی را در `shared/` بنویسد.

دو تصمیم که ارزش توضیح دارند:

**`instances: 1` عمدی است.** `lib/rate-limit.ts` شمارنده‌ی تلاش ناموفق را در حافظه‌ی همان پروسه نگه می‌دارد. با چند نمونه هر کدام شمارنده‌ی خودش را می‌داشت و سقف ۱۰ تلاش عملاً چند برابر می‌شد.

**`out_file: '/dev/null'` هم عمدی است.** لاگ خروجی استاندارد Next هر درخواست را با مسیرش می‌نویسد، یعنی «کاربر کدام برگه را باز کرد». همان چیزی که `access_log off` در Nginx جلویش را می‌گیرد. فقط `error_file` نگه داشته می‌شود.

## اسکریپت‌های توسعه (مرور)

اجرا از ریشه‌ی مخزن، نه روی سرور:

| دستور                | کار                                                                            |
| -------------------- | ------------------------------------------------------------------------------ |
| `pnpm check`         | typecheck + lint + کنتراست + اعتبارسنجی محتوا + تست محتوا + بازبینی حریم خصوصی |
| `pnpm test:content`  | نام‌های ممنوعه و یکپارچگی مسیر — بدون مرورگر                                   |
| `pnpm test:browser`  | پنج دسته‌ی مرورگری (نیازمند سرور بالا و `WH_TOKEN`)                            |
| `pnpm audit:privacy` | پنج بررسی حریم خصوصی                                                           |
| `pnpm drafts:list`   | فهرست گزینه‌های تأییدنشده                                                      |
| `pnpm contrast`      | کنتراست پالت و واریانت‌های آلفا                                                |

`prebuild` نگهبان پیش‌نویس و بازبینی حریم خصوصی را اجرا می‌کند — یعنی `install.sh` و `update.sh` هم خودبه‌خود از این دو رد می‌شوند و build با محتوای تأییدنشده یا با یک `fetch` خارجی تازه می‌شکند.
