# پرونده‌ی گرگ و جوجه‌تیغی — سند فازبندی اجرا

**نسخه:** ۱.۰
**مخاطب سند:** Claude Code
**زبان پروژه:** فارسی (RTL)
**هدف:** یک وب‌اپلیکیشن داستان تعاملی ۲۰ مرحله‌ای، خصوصی و توکن‌دار، مستقر روی سرور Ubuntu.

---

## ۰. قواعد کلی پروژه

این قواعد در تمام فازها الزامی‌اند و هیچ فازی بدون رعایت آن‌ها «تمام‌شده» حساب نمی‌شود.

1. **بدون اختراع محتوا.** هر مرحله‌ای که به داستان واقعی وابسته است (به‌ویژه مرحله ۳) تا زمان تحویل محتوا با `status: "pending-content"` علامت می‌خورد و در UI به‌صورت مرحله‌ی قفل‌شده‌ی موقت رندر می‌شود. حدس زدن ممنوع.
2. **هیچ پاسخی ثبت نمی‌شود.** انتخاب‌های کاربر فقط در `localStorage` مرورگر خودش می‌مانند. هیچ endpoint سمت سرور برای دریافت پاسخ‌ها نوشته نمی‌شود، هیچ لاگی از انتخاب‌ها نگه‌داشته نمی‌شود، هیچ analytics نصب نمی‌شود.
3. **هیچ مسیر بن‌بستی وجود ندارد.** هر گزینه‌ای قابل کلیک است و به مرحله‌ی بعد می‌رسد. تفاوت گزینه‌ها فقط در دیالوگ واکنش است.
4. **بدون نام و تصویر واقعی.** فقط شخصیت‌های حیوانی. هیچ اسم واقعی، عکس، اسکرین‌شات یا شماره‌ای در کد یا محتوا نمی‌آید.
5. **کیفیت پایه بدون استثنا:** موبایل‌فرست، `prefers-reduced-motion` محترم، focus قابل‌مشاهده با کیبورد، کنتراست حداقل AA.
6. **هر فاز مستند خودش را تولید می‌کند.** بدون مستند، فاز بسته نمی‌شود.

## ۳. جهت‌گیری بصری (الزام‌آور)

**مفهوم:** یک پرونده‌ی محرمانه‌ی شبانه که روی میز یک کارآگاه در جنگل باز می‌شود. کاغذ، مُهر، جوهر، مهتاب. نه «کارتون کودکانه»، نه «اپ مدرن مینیمال» — یک دوسیه‌ی کارتونی شبانه.

### ۳.۱ پالت (توکن‌های CSS)

```css
--shab: #101a2e; /* پس‌زمینه‌ی شب جنگل — رنگ غالب */
--kaj: #1e4034; /* سبز کاج، لایه‌ی میانی و مه */
--mahtab: #ede7d6; /* کاغذ پرونده و متن روی تیره */
--mohr: #a32b23; /* قرمز مُهر — فقط برای مُهر و تأکید نادر */
--tigh: #e0a458; /* کهربایی تیغ جوجه‌تیغی — رنگ تعامل و CTA */
--jooheh: #6b7a8f; /* خاکستری‌آبی برای متن ثانویه و خطوط */
```

قاعده: پس‌زمینه همیشه `--shab`. کارت پرونده `--mahtab`. تنها رنگ کلیک‌شدنی `--tigh` است. `--mohr` فقط روی مُهرها — اگر جای دیگری استفاده شد، اثرش می‌میرد.

### ۳.۲ تایپوگرافی

| نقش     | فونت                                                           | استفاده                            |
| ------- | -------------------------------------------------------------- | ---------------------------------- |
| نمایشی  | **مربا (Morabba) Bold**                                        | تیتر پرونده، عنوان مراحل، متن مُهر |
| متن     | **استعداد (Estedad)**                                          | دیالوگ‌ها، گزینه‌ها، توضیحات       |
| کاربردی | **وزیرمتن (Vazirmatn)** با `letter-spacing: .04em` و سایز کوچک | شماره‌ی پرونده، برچسب‌ها، فوتر     |

مقیاس تایپ: `12 / 14 / 16 / 20 / 26 / 34 / 48`. اعداد فارسی با `font-variant-numeric: tabular-nums`.
عمداً از وزیرمتن به‌عنوان فونت اصلی متن استفاده نمی‌کنیم — پیش‌فرض هر پروژه‌ی فارسی است و شخصیت ندارد.

### ۳.۳ عنصر امضا: **مُهر پرونده**

هر انتخاب کاربر با یک مُهر لاستیکی روی کارت ثبت می‌شود: مُهر از بالا با اسکیل ۲.۴ فرود می‌آید، ۳ تا ۷ درجه چرخش تصادفی می‌گیرد، لبه‌هایش با فیلتر SVG (`feTurbulence` + `feDisplacementMap`) پخش جوهر دارد، و صفحه ۳ پیکسل تکان می‌خورد. متن مُهر با محتوای انتخاب عوض می‌شود («ثبت شد»، «مردود»، «مشکوک»، «وکیل خبر شد»).

تمام جسارت بصری پروژه در همین یک عنصر خرج می‌شود. بقیه‌ی صفحه آرام و منظم می‌ماند.

### ۳.۴ چیدمان

کارت مرکزی `max-width: 620px`، حاشیه‌ی امن ۲۴ پیکسل، تمام‌قد در موبایل. گرگ سمت راست کارت، جوجه‌تیغی سمت چپ (RTL: راوی از راست وارد می‌شود). بافت کاغذ به‌صورت overlay با `mix-blend-mode: multiply` و opacity حداکثر ۰٫۰۸.

## ۴. مشخصات انیمیشن

| موقعیت       | مشخصات                                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| ورود مرحله   | کارت از پایین `y: 40 → 0`, `opacity 0 → 1`, `rotate: -1.5 → 0`, spring `{stiffness: 260, damping: 26}`                                   |
| خروج مرحله   | کارت به بالا-چپ می‌لغزد `x: -30, y: -20, rotate: 2, opacity: 0`، مدت ۰٫۳۵ ثانیه                                                          |
| مُهر         | `scale: 2.4 → 1`, `opacity: 0 → 1`, `rotate: random(3,7)`, spring `{stiffness: 420, damping: 18}` + شیک ۳px روی والد                     |
| مه (اسکین ۱) | دو لایه SVG با `translateX` بی‌نهایت، ۴۰ و ۶۵ ثانیه، جهت‌های مخالف                                                                       |
| نقشه         | پین با `scale: 0 → 1.2 → 1` و bounce؛ سپس دایره‌ی جوهر `scale: 0 → 1, opacity: .6 → 0`                                                   |
| حباب‌های فکر | `Reorder` از Framer Motion، شناور بی‌کار با `y: [0,-6,0]` تکرار ۳ ثانیه‌ای، فاز تصادفی برای هر حباب                                      |
| نوار پیشرفت  | مُهر کوچک به‌ازای هر مرحله؛ با تکمیل، مُهر رنگ می‌گیرد                                                                                   |
| کاهش حرکت    | با `prefers-reduced-motion: reduce` همه‌ی موارد بالا به `opacity` ساده‌ی ۰٫۲ ثانیه تبدیل می‌شوند. مُهر بدون شیک و بدون چرخش ظاهر می‌شود. |

## ۵. مدل داده‌ی محتوا

`content/schema.ts` — این قرارداد هسته‌ی پروژه است و قبل از هر کد UI نوشته می‌شود.

```ts
export type SkinId = 'cover' | 'interrogation' | 'map' | 'mind' | 'ending';
export type Speaker = 'nazoo' | 'wolf' | 'hedgehog' | 'owl' | 'squirrel' | 'system';

export type Option = {
  id: string;
  label: string;
  reaction: string; // دیالوگ واکنش
  stamp?: string; // متن مُهر
  reactionSpeaker?: Speaker;
};

export type Interaction =
  | { kind: 'choice'; multi: false; options: Option[] }
  | { kind: 'choice'; multi: true; options: Option[]; min?: number; max?: number }
  | { kind: 'sort'; items: { id: string; label: string }[]; message: string }
  | {
      kind: 'find';
      hotspots: {
        id: string;
        x: number;
        y: number;
        r: number;
        correct: boolean;
        reaction: string;
      }[];
    }
  | {
      kind: 'split';
      cards: { id: string; label: string; bucket: string }[];
      buckets: { id: string; label: string }[];
      message: string;
    }
  | { kind: 'pick'; options: Option[]; note: string }; // انتخاب آزاد، بدون درست/غلط

export type Stage = {
  id: string; // 's01' … 's20'
  act: 1 | 2 | 3 | 4 | 5;
  title: string;
  skin: SkinId;
  mapNode?: string; // نقطه‌ای که با اتمام این مرحله روشن می‌شود
  lines: { speaker: Speaker; text: string }[];
  interaction: Interaction;
  closing?: string; // پیام بعد از انتخاب
  status?: 'ready' | 'pending-content';
};
```

هر ۲۰ فایل با `zod` در زمان build اعتبارسنجی می‌شوند. اگر مرحله‌ای گزینه‌ی بدون `reaction` داشته باشد، build شکست می‌خورد.

### فاز ۱ — سیستم طراحی

**هدف:** هر رنگ، فونت و فاصله‌ای که در فازهای بعد استفاده می‌شود، اینجا تعریف و دیده شود.

**خروجی مستند:** `docs/01-design-system.md` — پالت با کد رنگ، مقیاس تایپ، قواعد استفاده، اسکرین‌شات kit

### فاز ۲ — موتور داستان

**هدف:** بتوان با یک فایل محتوای ساختگی، کل جریان را طی کرد.

**کارها:**

- `content/schema.ts` + اعتبارسنجی zod
- `lib/engine.ts`: مرحله‌ی بعد/قبل، اعتبارسنجی انتخاب، محاسبه‌ی نقاط نقشه‌ی روشن‌شده

- روت `app/story/[stageId]/page.tsx` با `AnimatePresence`
- دکمه‌ی «شروع دوباره» که `localStorage` را پاک می‌کند
- سه مرحله‌ی نمونه با محتوای ساختگی برای تست

**خروجی مستند:** `docs/02-story-engine.md` — دیاگرام جریان، شکل state، نحوه‌ی افزودن مرحله‌ی جدید

**پذیرش:** با محتوای ساختگی می‌توان از مرحله ۱ تا ۳ رفت، رفرش کرد و در همان مرحله ماند.

**قواعد نگارش دیالوگ:**

- شوخی‌ها به گرگ برمی‌گردد، نه به جوجه‌تیغی. گرگ سوژه‌ی طنز است.
- هیچ گزینه‌ای کاربر را «غلط» اعلام نمی‌کند. بدترین حالت: مُهر «مشکوک» و یک جمله‌ی خنده‌دار.
- هر گزینه حتماً `reaction` دارد؛ گزینه‌ی بی‌واکنش یعنی گزینه‌ی تنبیهی.
- مرحله ۲۰: فقط گزینه‌ی «لازم نیست امروز درباره‌ی آینده تصمیم بگیریم» مسیر آرام را باز می‌کند؛ بقیه هم پایان محترمانه دارند و هیچ‌کدام کاربر را به مرحله‌ی قبل برنمی‌گرداند.

**خروجی مستند:** `docs/03-stages.md` — متن کامل هر ۲۰ مرحله با تمام گزینه‌ها و واکنش‌ها، به‌عنوان مرجع ویرایش

**پذیرش:** zod همه‌ی ۲۰ فایل را پاس می‌کند؛ عبور کامل از ۱ تا ۲۰ بدون خطا؛ هر ۹ نقطه‌ی نقشه در پایان روشن‌اند.

### فاز ۵ — دروازه‌ی ورود و حریم خصوصی

**هدف:** سایت خصوصی بماند و قابل حذف کامل باشد.

**کارها:**

- `/gate`: ورودی توکن؛ مقایسه با `ACCESS_TOKEN` در `api/verify` با مقایسه‌ی زمان‌ثابت
- کوکی `httpOnly`, `secure`, `sameSite: strict`, عمر ۳۰ روز
- `middleware.ts`: بدون کوکی معتبر → ریدایرکت به `/gate`
- انقضای لینک: اگر `Date.now() > LINK_EXPIRES_AT` صفحه‌ی «این پرونده بسته شد» نمایش داده می‌شود
- `robots.txt` با `Disallow: /` + متاتگ `noindex, nofollow, noarchive` + هدر `X-Robots-Tag`
- Nginx: `add_header X-Robots-Tag "noindex, nofollow";` و بستن `/api` به بیرون جز same-origin
- **بازبینی صریح:** grep روی کل مخزن برای اطمینان از نبود fetch/POST خروجی، analytics، Sentry یا هر تله‌متری
- صفحه‌ی `/about-this`: توضیح شفاف اینکه هیچ پاسخی ذخیره یا ارسال نمی‌شود و لینک تاریخ انقضا دارد

**خروجی مستند:** `docs/05-privacy.md` — چه چیزی ذخیره می‌شود (فقط localStorage)، چه چیزی نمی‌شود، نحوه‌ی حذف کامل

**پذیرش:** بدون توکن هیچ محتوایی از داستان قابل‌دسترس نیست (حتی از طریق روت مستقیم `/story/s07`). خروجی `curl -I` هدر noindex دارد.

### فاز ۸ — اسکریپت‌ها و استقرار

**هدف:** نصب، به‌روزرسانی و حذف کامل با یک دستور.

#### `scripts/install.sh`

```
Usage: sudo ./install.sh --domain <domain> --email <email> [--dir /var/www/wh] [--no-ssl]
```

مراحل:

1. بررسی root، تشخیص Ubuntu، بررسی وجود دامنه در DNS
2. نصب Node.js 22 LTS از NodeSource اگر نبود؛ نصب `pnpm` و `pm2` سراسری
3. ساخت کاربر سیستمی `wolfapp` بدون shell
4. کپی سورس به `--dir`، `pnpm install --frozen-lockfile`، `pnpm build`
5. ساخت `.env` از `.env.example`؛ تولید `ACCESS_TOKEN` با `openssl rand -hex 16`؛ **چاپ توکن و لینک نهایی در انتهای اجرا**
6. نصب `deploy/ecosystem.config.cjs` و `pm2 start` + `pm2 save` + `pm2 startup`
7. رندر `nginx.conf.template` با دامنه، `nginx -t`، ریلود
8. certbot برای SSL (مگر `--no-ssl`)
9. `ufw allow 22,80,443` و فعال‌سازی
10. `systemd` timer روزانه برای `backup.sh`
11. بررسی سلامت: `curl -f https://<domain>/gate` — در صورت شکست، خروج با کد خطا و راهنمای رفع

اصول: `set -euo pipefail`، idempotent (اجرای دوباره خراب نکند)، هر مرحله لاگ رنگی، در صورت خطا rollback همان مرحله.

#### `scripts/update.sh`

```
Usage: sudo ./update.sh [--ref main] [--rollback]
```

1. `backup.sh` قبل از هر کاری
2. `git fetch && git checkout <ref>`
3. `pnpm install --frozen-lockfile && pnpm build` در پوشه‌ی موقت
4. فقط در صورت موفقیت build، سواپ اتمیک با symlink `current →  releases/<timestamp>`
5. `pm2 reload` (بدون downtime)
6. health check؛ در صورت شکست، بازگشت خودکار symlink به ریلیز قبلی
7. نگه‌داشتن ۵ ریلیز آخر
8. `--rollback` بدون آرگومان دیگر: بازگشت به ریلیز قبلی

#### `scripts/uninstall.sh`

```
Usage: sudo ./uninstall.sh [--purge] [--keep-cert] [--yes]
```

1. تأیید تعاملی با تایپ نام دامنه (مگر `--yes`)
2. `pm2 delete` + `pm2 save`
3. حذف سایت Nginx و ریلود
4. `certbot delete` مگر `--keep-cert`
5. حذف پوشه‌ی برنامه
6. `--purge`: حذف کاربر `wolfapp`، پشتیبان‌ها، تایمر systemd و قوانین ufw مربوطه
7. چاپ فهرست چیزهایی که حذف شدند و آنچه دست‌نخورده ماند

#### `scripts/backup.sh`

آرشیو `.env` و پوشه‌ی `content/` در `/var/backups/wolf-hedgehog/<date>.tar.gz`، نگه‌داشتن ۱۴ روز. (دیتابیسی وجود ندارد.)

**خروجی مستند:** `docs/08-deploy.md` (نیازمندی سرور، نصب گام‌به‌گام، رفع اشکال) و `docs/09-scripts.md` (پارامترها، کدهای خروج، نمونه‌ی خروجی هر اسکریپت)

**پذیرش:** روی یک VPS تازه، `install.sh` تا سایت زنده بدون دخالت دستی اجرا شود؛ `update.sh` بدون قطعی؛ `uninstall.sh --purge` سرور را به حالت اول برگرداند.

## ۷. ترتیب اجرا برای Claude Code

فازها **ترتیبی** اجرا می‌شوند. فاز بعدی شروع نمی‌شود مگر:

1. معیارهای پذیرش فاز فعلی سبز باشند
2. مستند فاز نوشته شده باشد
3. `docs/CHANGELOG.md` به‌روز شده باشد
4. یک commit با پیام `phase(N): <خلاصه>` ثبت شده باشد

استثنا: فاز ۴ (محتوا) می‌تواند موازی با فاز ۳ (اسکین‌ها) پیش برود، چون به هم وابسته نیستند.
